# Contributing to ReGP

How to set up a local development environment, build the project, and compare your result against the original game binaries.

## Prerequisites

- **Windows** — the project builds 32-bit Windows executables; only 32-bit toolchains are supported.
- **CMake ≥ 3.20**.
- **Microsoft Visual C++ 6.0** — a portable copy is included as a git submodule at `3rdparty/MSVC600`. Fetch it with:

  ```shell
  git submodule update --init --recursive
  ```

- **[uv](https://docs.astral.sh/uv/)** for the Python environment used by the comparison tooling.
- The **DirectX 6 SDK** is already bundled in `3rdparty/dx6` — nothing to install.

## Setting up the Python environment

The binary comparison uses [reccmp](https://github.com/isledecomp/reccmp), a Python tool installed from [`pyproject.toml`](pyproject.toml) into a `.venv` virtualenv at the repository root:

```shell
uv sync
```

You can either activate the environment (`.\.venv\Scripts\activate.ps1`, or `.\.venv\Scripts\activate.bat` in CMD), or prefix commands with `uv run`.

## Building

The build produces `StuntGP.exe` and `StuntGP_D3D.exe` (plus a generated `reccmp-build.yml`) at the root of your build directory.

### With MSVC 6.0 (the original compiler)

1. Open CMD or PowerShell in the repository root.
2. Load the MSVC 6 environment:
   - CMD: `3rdparty\MSVC600\VC98\Bin\VCVars32.BAT`
   - PowerShell: `.\3rdparty\MSVC600\VC98\Bin\VCVARS32.ps1`
3. Configure the project:

   ```shell
   cmake . -B build -G "NMake Makefiles" -DCMAKE_BUILD_TYPE=RelWithDebInfo
   ```

   `CMAKE_BUILD_TYPE` can be `Debug`, `Release`, or `RelWithDebInfo`; use `RelWithDebInfo` for comparison against the original.
4. Build — run it **twice**, as some inputs are only picked up on the second pass:

   ```shell
   cmake --build build
   cmake --build build
   ```

### With a modern compiler

The code also compiles with recent Visual Studio, which is handy for iterating without MSVC 6. Use a separate build directory so you don't clobber your MSVC 6 build:

1. Open CMD and load the Visual Studio environment, e.g.:

   ```bat
   "C:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars32.bat"
   ```

2. Configure and build:

   ```shell
   cmake . -B build_modern -G "NMake Makefiles" -DCMAKE_BUILD_TYPE=RelWithDebInfo
   cmake --build build_modern
   ```

## Comparing against the original (reccmp)

1. Create an `originals` directory at the repository root and copy your original `.exe` files into it. The directory is git-ignored — every developer provides their own copy of the game.
2. Register the originals in the local reccmp user config:

   ```shell
   uv run reccmp-project detect --search-path originals
   ```

3. Build the project (see above), then register the recompiled binaries:

   ```shell
   uv run reccmp-project detect --what recompiled --search-path build
   ```

4. Run the comparison for a target:

   ```shell
   uv run reccmp-reccmp --target STUNTGP_D3D
   ```

   The available targets are listed in [`reccmp-project.yml`](reccmp-project.yml) (`STUNTGP`, `STUNTGP_D3D`, and `CONFIG` when built with `-DSTUNTGP_BUILD_CONFIG=ON`).

### Updating the status charts

The progress charts in [status/](status/) are generated by reccmp. To regenerate them after a build:

```shell
uv run reccmp-reccmp --target STUNTGP --svg .\status\StuntGP.svg --html .\status\StuntGP.html --json .\status\StuntGP.json -T 803
uv run reccmp-reccmp --target STUNTGP_D3D --svg .\status\StuntGP_D3D.svg --html .\status\StuntGP_D3D.html --json .\status\StuntGP_D3D.json -T 2259
```

## Git hooks (optional)

The repository ships a pre-commit hook in [.githooks/](.githooks/) that rebuilds the project and regenerates the status charts before each commit. It is **not** enabled by default; to opt in:

```shell
git config core.hooksPath .githooks
```

See [.githooks/README.md](.githooks/README.md) for details. The hook expects PowerShell 7 (`pwsh`), CMake, and the `.venv` from above.
